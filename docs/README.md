# 📚 Documentación — Gestor de Inventarios

Este directorio contiene la documentación técnica y funcional del proyecto **Gestor de Inventarios**, una aplicación web orientada a la administración y control de productos mediante operaciones CRUD (Crear, Leer, Actualizar y Eliminar).

La documentación registra las distintas etapas del ciclo de vida del desarrollo de software, desde la identificación de necesidades y definición de requisitos hasta el diseño, la implementación, las pruebas y el mantenimiento.

## 🎯 Objetivo de la documentación

Organizar y mantener un registro estructurado de las decisiones, requisitos, diseños, procesos y pruebas realizados durante el desarrollo del sistema.

Esta documentación busca facilitar:

- La comprensión general del proyecto.
- La trazabilidad de los requisitos.
- La consulta de historias de usuario y casos de uso.
- El mantenimiento y la evolución del software.
- La identificación de funcionalidades implementadas.
- La validación del funcionamiento de la aplicación.

## 📁 Organización de la documentación

La documentación se divide en las siguientes áreas:

| Área | Descripción |
|---|---|
| **Visión y alcance** | Define el problema, los objetivos y los límites del sistema. |
| **Requisitos** | Describe los requisitos funcionales y no funcionales. |
| **Historias de usuario** | Registra las funcionalidades desde la perspectiva del usuario. |
| **Casos de uso** | Describe las interacciones entre los usuarios y el sistema. |
| **Diseño y diagramas** | Representa la estructura, los componentes y los flujos de la aplicación. |
| **Modelo de datos** | Documenta las entidades, sus atributos y la estructura de almacenamiento de la información. |
| **Pruebas** | Documenta los escenarios de validación y sus resultados. |
| **Manual de usuario** | Explica cómo utilizar las funcionalidades del sistema. |
| **Manual técnico** | Describe aspectos técnicos de la aplicación y su mantenimiento. |

Nota: En la versión 1.0, el sistema utiliza localStorage para almacenar información. La sección de modelo de datos permitirá documentar la estructura actual y preparar futuras implementaciones con bases de datos.

## 🔄 Ciclo de vida del desarrollo

La documentación sigue una organización basada en las principales etapas del desarrollo de software.

**1. Análisis:** identificación del problema, necesidades y requisitos.

**2. Diseño:** definición de la estructura, interfaces, diagramas y comportamiento del sistema.

**3. Implementación:** desarrollo de funcionalidades mediante HTML, CSS y JavaScript.

**4. Pruebas:** ejecución de casos de prueba para verificar el cumplimiento de los requisitos.

**5. Despliegue:** publicación de la aplicación mediante GitHub Pages y automatización con GitHub Actions.

**6. Mantenimiento:** corrección de errores, mejoras y evolución hacia nuevas versiones.

## 🧪 Pruebas y validación

Los casos de prueba permiten verificar el comportamiento esperado del sistema.

Entre los procesos que se validan se encuentran:

- Registro e inicio de sesión.
- Validaciones de formularios.
- Protección de acceso al dashboard.
- Registro de productos.
- Consulta de productos almacenados.
- Edición y eliminación de productos.
- Persistencia de información mediante localStorage.
- Comportamiento de la interfaz.

Los resultados se documentan para identificar errores, registrar correcciones y comprobar el funcionamiento de las funcionalidades desarrolladas.

## 📝 Mantenimiento de la documentación

La documentación se actualizará conforme avance el desarrollo del proyecto.

Se procurará mantener la correspondencia entre los requisitos, las funcionalidades implementadas, los casos de prueba y el comportamiento real de la aplicación.

Los cambios importantes podrán registrarse mediante Git para conservar su historial y facilitar futuras revisiones.
